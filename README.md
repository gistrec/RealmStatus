# RealmStatus

Telethon-бот для серверов Minecraft и Terraria. По умолчанию раз в минуту обновляет [сообщение №38](https://t.me/c/3410760885/38) в чате `-1003410760885`. Показывает суммарный онлайн, список игроков по играм и время обновления по Москве.

По умолчанию под каждым сервером остаются игроки, чьи визиты известны боту. Под ником каждого игрока указана его активность. Сначала идут игроки онлайн, затем вышедшие. В каждой группе порядок определяется суммарным временем игры. В первую минуту после выхода отображается «играл недавно». Длинный список можно листать кнопками в том же сообщении.

История хранится в `.state/player-roster.json`. Бот загружает прежние визиты локального Minecraft Java из статистики мира и журналов, а для Terraria использует данные tMapOnline. Для источников, которые передают только текущий онлайн, бот учитывает визиты с момента первого наблюдения.

## Запуск на Mac

Нужен Python 3.12+. Скопируйте `.env.example` в `.env` и заполните `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и `TELEGRAM_BOT_TOKEN`. Чаты, сообщение и доступ к командам задаются в `games.toml`.

```sh
make setup
make preview
make start
```

- `make preview` опрашивает серверы и выводит текст локально. Он не соединяется с Telegram.
- `make start` запускает бота в фоне и ждёт подключения к Telegram. Лог пишется в `.state/bot.log`.
- `make stop` штатно останавливает бота.
- `make run` оставляет бота в текущем терминале. Для остановки также работает `Ctrl+C`.
- Для редактирования используйте аккаунт бота, который опубликовал целевое сообщение, либо аккаунт с правом редактировать посты в канале. При ошибке прав бот оставляет сообщение на месте и пишет причину в консоль.
- Для закрытой группы при первой настройке отправьте `/status@имя_бота` в целевой чат, чтобы Telethon получил его данные и сохранил их в сессии. Для публичного чата можно задать `chat_username` в TOML.
- Для Terraria нужен запущенный веб-сервис tMapOnline с телеметрией. Из папки `../_python/terraria-world-viewer` его можно запустить командой `.venv/bin/tmaponline --config config.yaml serve`. При работающем сервере и недоступной телеметрии в сообщении появится статус «недоступен».

## Настройка Telegram

В `games.toml` укажите чат и ID сообщения, которое бот редактирует. Чаты для команд можно настроить отдельно.

```toml
[telegram]
chat_id = -1003410760885
message_id = 38
control_chat_ids = [-1003410760885]
allowed_user_ids = []
allow_all_users = false
show_offline_players = true
```

- `control_chat_ids` принимает список ID чатов. Для группы или канала указывайте полный отрицательный ID, включая `-100` для супергрупп и каналов.
- Добавьте числовой Telegram ID пользователя в `allowed_user_ids`, чтобы он мог выполнять команды в личке с ботом. При `allow_all_users = false` этот список также определяет, кто может выполнять команды в чатах из `control_chat_ids`.
- Если нужно открыть команды всем пользователям указанных чатов, установите `allow_all_users = true`. В группах можно адресовать команду боту через суффикс `@имя_бота`.
- Дополнительно можно указать `chat_username` публичного чата и `update_interval_seconds` для частоты обновления. Изменения в TOML вступают в силу после перезапуска бота.
- `show_offline_players = false` показывает только игроков онлайн у всех серверов. История продолжает накапливаться, и `true` снова показывает всех известных игроков.

В старых конфигурациях без блока `[telegram]` продолжают работать прежние переменные `TELEGRAM_CHAT_ID`, `TELEGRAM_MESSAGE_ID`, `TELEGRAM_CONTROL_CHAT_ID` и `TELEGRAM_ADMIN_IDS`.

## Команды в Telegram

| Команда | Действие |
| --- | --- |
| `/status` | Запросить обновление сообщения |
| `/minecraft_start` | Запустить Purpur |
| `/minecraft_stop` | Штатно остановить Purpur |
| `/terraria_start` | Запустить tModLoader в Terminal |
| `/terraria_stop` | Сохранить мир и остановить tModLoader |
| `/tunnel_start` | Запустить общий туннель FRPC |
| `/tunnel_stop` | Остановить общий туннель FRPC |
| `/tunnel_restart` | Остановить и снова запустить FRPC |
| `/emoji_sync` | Обновить набор эмодзи и получить ссылку на него |

У бота должна быть активная пользовательская сессия macOS, чтобы команды запуска могли открыть Terminal. Для обоих серверов используются существующие Make-цели из соседних проектов. При остановке одного сервера общий FRPC продолжает работать.

## Набор эмодзи

В [папке исходников](assets/emoji/source/) лежат иконки Minecraft, Terraria и Stardew Valley. `make emoji-prepare` создаёт из них прозрачные PNG 100 × 100 и добавляет доступные портреты игроков в `assets/emoji/generated/png/`. Команда собирает изображения локально.

Для публикации укажи Telegram ID владельца в `[emoji_pack].owner_id`, установи `enabled = true` и перезапусти бота. Если бот ещё не знает владельца, сначала открой его в Telegram и отправь `/start`. Бот создаёт набор при запуске и сверяет головы раз в минуту по умолчанию (`refresh_seconds = 60`). При изменении портрета обновляется локальный PNG и заменяется эмодзи того же игрока. Команда `/emoji_sync` запускает синхронизацию вручную и возвращает ссылку на набор.

В сообщении с онлайном бот использует иконку из набора рядом с названием игры. В списках Minecraft и Terraria слева от ника отображается готовый эмодзи головы. Пока его нет, слева ничего не добавляется. Рядом с ником показывается длительность текущей сессии. Для Terraria время берётся из tMapOnline, если API отдаёт данные сессии. Для Minecraft и при отсутствии данных сессии отсчёт начинается с момента, когда бот увидел игрока онлайн. Telegram может отклонить пользовательские эмодзи. Тогда бот повторяет редактирование с обычными иконками игр и никами без голов.

Головы Minecraft строятся из сохранённых скинов SkinsRestorer. Для Terraria используются готовые портреты tMapOnline. Изображение попадает в набор, когда оно становится доступно в источнике. Подробнее о папках и файлах см. [описание изображений](assets/emoji/README.md).

## Туннель FRPC

```toml
[tunnel]
enabled = true
directory = "../makstashkevich.com"
start_target = "tunnel-up"
stop_target = "tunnel-down"
# restart_target = "tunnel-restart"
```

`directory` указывает на проект с Makefile. В `start_target` и `stop_target` впиши имена целей для запуска и остановки. Если в Makefile есть собственная цель перезапуска, укажи её в `restart_target`. Иначе бот выполнит остановку и запуск по очереди. Команды туннеля подчиняются тем же правилам доступа, что и команды серверов. Запуск игр независим от запуска FRPC.

Для серверов с прямым доступом, например на VPS, установи `enabled = false`. Бот отключит команды FRPC после перезапуска. Если туннель уже работает и его нужно погасить, используй `/tunnel_stop` перед отключением команд.

## Настройка игр

Редактируйте локальный `games.toml`. В новом клоне скопируйте `games.example.toml` в `games.toml`. Настройки применяются при запуске бота. Проверьте результат через `make preview`.

- `enabled = false` скрывает игру из сообщения, отключает опрос и команды управления.
- `source` выбирает блок `[games.<id>.sources.<source>]`. В нём задаются адрес, порт или ID мира. Можно хранить параметры нескольких источников и переключать их одной строкой.
- Блок `control` в выбранном локальном источнике включает команды `/<id>_start` и `/<id>_stop`. Поля `start_target` и `stop_target` задают имена целей из Makefile сервера. По умолчанию это `start` и `stop`. Без блока `control` игра только показывает онлайн. Относительные пути считаются от файла конфигурации.

| Источник | Параметры |
| --- | --- |
| `minecraft_java` | `host` и `port` Java-сервера |
| `minecraft_realms` | `world_id` мира Realms |
| `terraria_viewer` | `host` и `port` игрового сервера, `url` API tMapOnline |
| `stardew_api` | `base_url` или `STARDEW_API_BASE_URL`, токен `STARDEW_API_TOKEN` из `.env` |

Добавляйте отдельные блоки `[games.<id>]` для нескольких серверов с одним типом источника. ID определяет имя команд, а порядок блоков определяет порядок в сообщении. Через `GAMES_CONFIG` можно указать другой TOML-файл. Если локального файла нет, бот берёт шаблон с учётом настроек игр из прежнего `.env`. После создания локального TOML перенесите туда прежние адреса, порты и переключатели.

## Переключение Minecraft на Realms

1. В `[games.minecraft]` выберите `source = "minecraft_realms"`. Укажите `world_id` в соответствующем блоке источника и параметры `MYSQL_*` существующей базы RealmStatus в `.env`.
2. Выполните `make setup-realms`. На Mac бот использует PyMySQL с проверкой сертификата и имени сервера.
3. Если в базе ещё нет действующих токенов, выполните `make realms-login` и завершите вход Microsoft. Если в конфигурации несколько миров Realms, укажите ID блока через `.venv/bin/python -m realm_status --realms-login <id>`.
4. Выполните `make preview`, затем перезапустите бота. Для возврата к Purpur выберите `source = "minecraft_java"`.

Для Stardew Valley установите `enabled = true` в `[games.stardew]` и заполните параметры источника `stardew_api`.

Старый обработчик `main.py`, статистика в `tg.py`, резервные копии и облачный деплой сохранены. Используйте один процесс публикации на одно сообщение, чтобы старый и новый боты не перезаписывали его по очереди.
