# Архитектура RealmStatus

На ветке `stashkevich` добавлен отдельный процесс Telethon для запуска на Mac. Оригинальный облачный обработчик остаётся самостоятельной точкой входа.

## Компоненты

| Файл | Ответственность |
| --- | --- |
| `realm_status/__main__.py` | Собирает приложение из настроек, создаёт источники и контроллеры, запускает бота или локальное превью |
| `realm_status/settings.py` | Читает `.env` и общий TOML, валидирует адрес сообщения и политику доступа к командам |
| `realm_status/games.py` | Читает список игр из TOML, выбирает активные адаптеры и привязывает разрешённое управление к ID игры |
| `realm_status/status.py` | Описывает контракт `StatusSource`, собирает результаты параллельно и форматирует сообщение |
| `realm_status/sources/local.py` | Получает счётчик и выборку игроков по Java Status. Для Terraria сверяет TCP-порт, подключение телеметрии и свежесть снимка |
| `realm_status/sources/legacy.py` | Подключает Realms и Stardew Valley к общему контракту онлайн-статуса |
| `auth/realms.py` | Переиспользует Microsoft/Xbox/Minecraft и хранилище токенов из прежнего кода |
| `realm_status/telegram.py` | Разрешает чат, редактирует заданное сообщение, проверяет чат и ID автора команд |
| `realm_status/control.py` | Запускает Make-цели из локального TOML. Серверы и общий FRPC имеют независимые контроллеры |
| `realm_status/emoji/` | Собирает изображения, нормализует их и создаёт или пополняет набор через Telegram Bot API |
| `main.py`, `tg.py`, `deploy.sh` | Сохраняют облачный сценарий с прежним форматированием, статистикой и ссылкой на скачивание резервной копии |

## Как проходят запросы

1. `TelegramBot` запрашивает у `StatusBoard` новый текст при запуске, по таймеру и после команды. У цикла публикации один владелец: параллельные команды только сигнализируют, что статус надо обновить.
2. `StatusBoard` запускает источники одновременно. Сбой одного источника не сбрасывает остальные значения. «Недоступен» отличается от пустого списка и остановленного сервера.
3. Telethon редактирует ровно настроенный ID сообщения. Идентификатор чата проверяется при разрешении по username, переписка не используется как источник команд запуска.
4. Команды проходят проверку списка чатов и числового ID автора. В режиме `allow_all_users` список пользователей не применяется, а список чатов остаётся обязательным. Суффикс команды должен адресоваться этому боту. Контроллер игры выполняет `start` и `stop` для включённой игры с локальным источником и блоком `control`. Проект Terraria проверяет владельца порта перед сигналом сохранения.
5. Контроллер FRPC создаётся при `[tunnel].enabled = true`. Перезапуск вызывает `restart_target` или пару `stop_target` и `start_target` под одной блокировкой. Make получает проверенное имя цели из TOML отдельным аргументом. Команды игр не вызывают цели FRPC.
6. `EmojiPack` синхронизирует изображения в фоновом цикле и по `/emoji_sync`. Локальный журнал хранит хэши загруженных PNG. Из полученного набора адаптер передаёт ID трёх иконок в `StatusBoard`. Telethon оформляет эти значки как сущности `MessageEntityCustomEmoji` при редактировании статуса.

Локальный режим не зависит от MySQL. Источник Realms использует прежнее хранилище и сетевые таймауты. Выбор источника применяется при запуске. Java Status может вернуть часть ников. Сообщение показывает полный счётчик и отмечает число игроков, чьи ники сервер не передал.

## При изменениях

- Формат сообщения и опрос источников меняйте в `StatusBoard` и адаптерах. Telegram и Make остаются внешними границами приложения.
- При изменении управляющих команд проверяйте чат, автора, суффикс бота, конкурирующие команды и работу команд в режиме Realms.
- `make preview` проверяет локальный опрос и форматирование. Реальное редактирование требует аккаунта с доступом к сообщению. Realms и Stardew требуют доступа к своим сервисам.
